# Диагностический конвейер — прототип v0.1

## Назначение

Программа принимает подготовленные наблюдения, проверяет их
происхождение, формирует контекст, выделяет поддерживаемые
сигнатуры ошибок и создаёт диагностический отчёт.

По выбору пользователя запускается локальная модель Qwen3-1.7B.
Её ответ сохраняется отдельно от результатов правил.

Это прототип поддержки инженера, а не система автоматического
установления первопричины или исправления инфраструктуры.

## Запуск

Команды выполняются из корня репозитория.

### Только правила

python3 src/run_pipeline.py \
  experiments/context-method-dev/incident-003-pair/input.json \
  --mode rules-only \
  --output-dir results/raw/example-rules-001

### С локальной моделью

source .venv/bin/activate

python src/run_pipeline.py \
  experiments/context-method-dev/incident-003-pair/input.json \
  --mode with-model \
  --seed 42 \
  --max-new-tokens 1536 \
  --output-dir results/raw/example-model-001

Для второго режима требуются доступная GPU, окружение PyTorch
и модель с закреплённой ревизией в локальном кэше.
Работающий Docker-стенд для обработки сохранённых наблюдений
не требуется.

Для каждого запуска нужна новая папка output-dir.

## Входные данные

Поддерживаются подготовленные данные сборщика контекста
схем 0.1 и 0.2. Это не универсальный импорт произвольных журналов.

Наблюдения содержат идентификаторы, текст и сведения
о происхождении. Файлы, указанные в provenance, должны
быть доступны; их хеши и наличие выдержек проверяются.

## Результаты

- report.md — отчёт для чтения;
- report.json — структурированный отчёт;
- pipeline-status.json — режим, этап, статус и хеши;
- context/ — запросы, диагностические факты и манифест;
- context.log — журнал сборки;
- model/ и model.log — результаты и журнал модели,
  только для режима with-model.

## Разделение сведений

Результаты правил содержат распознанные сигнатуры,
точные цитаты, границы вывода и предложенные проверки.

Цитаты сверяются с входными наблюдениями.
Трактовки правил являются дополнительными знаниями,
а не буквальным содержимым журналов.

Ответ модели не проверяется семантически и может ошибаться.
Он не изменяет раздел результатов правил.
Предложенные команды и проверки автоматически не выполняются.

## Поддерживаемые сигнатуры

- отказ парольной аутентификации;
- ошибка разрешения имени узла;
- сообщение об отсутствии отношения;
- отказ доступа к таблице или отношению из-за прав.

Отсутствие совпадения не означает отсутствия сбоя.

## Ограничения

- Временной аудит не исключает наблюдения автоматически.
- Подлинность и полнота исходных журналов не гарантируются.
- Хеши позволяют обнаруживать изменения, но не доказывают
  достоверность источника.
- Семантическая корректность ответа модели не проверяется.
- Автоматическое продолжение прерванного запуска не реализовано.
- Обработка KeyboardInterrupt предусмотрена в коде,
  но отдельным интеграционным тестом не подтверждена.
- Принудительное завершение процесса может оставить
  последний записанный статус running.
- Снижение ошибок модели и экономия времени инженера
  экспериментально не установлены.

## Проверки

python3 -m unittest discover -s tests -p 'test_diagnostic*.py' -v
python3 -m unittest discover -s tests -p 'test_pipeline_failures.py' -v

Проверены успешный запуск без модели, отказ при изменённом
источнике, отклонение неверной цитаты и сохранность результатов
при повторном запуске в существующую папку.

Оба режима также проверены вручную на инциденте 003.

## При ошибке

Посмотреть pipeline-status.json и журнал соответствующего этапа.
Сохранить незавершённую папку для разбора.
Не удалять исходные результаты и не подменять статус вручную.
После исправления использовать новую папку запуска.

## Сохранение результатов

Каталог results/raw может исключаться из Git.
Для воспроизводимости отдельно сохранять исходные наблюдения,
выводы модели, отчёты, журналы, параметры и манифесты.
Наличие хеша в Git не заменяет резервную копию самого файла.

## Выбор контекста для модели

Параметр --context-mode применяется к режиму with-model:

- baseline — наблюдения без диагностического блока правил;
- with-rules — те же наблюдения с диагностическим блоком.
  Это значение по умолчанию.

Пример запуска без диагностической подсказки:

python src/run_pipeline.py \
  experiments/context-method-dev/incident-003-pair/input.json \
  --mode with-model \
  --context-mode baseline \
  --seed 42 \
  --max-new-tokens 1536 \
  --output-dir results/raw/example-baseline-001

Для второго условия используется --context-mode with-rules
и другая папка output-dir.

В обоих случаях итоговый отчёт содержит отдельный раздел
результатов правил. В baseline этот раздел формируется
для отчёта, но не передаётся модели.

При сравнении качества генерации оценивается исходный answer.txt,
а не объединённый отчёт. Польза объединённого отчёта для инженера
требует отдельной оценки.

Выбранное условие записывается в pipeline-status.json
и в происхождении отчёта. Совместимость запросов проверяется
интеграционным тестом с заменой модели, без GPU.

Сочетание rules-only и context-mode baseline отклоняется:
при отсутствии модели оно не задаёт отдельного условия.
