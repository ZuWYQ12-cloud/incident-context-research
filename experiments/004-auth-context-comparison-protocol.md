# Сравнение контекста: отказ аутентификации PostgreSQL

## Статус и цель

Дополнение к experiments/003-context-comparison-protocol.md.
Фиксируется до сравнительных запусков второго инцидента.

Цель — проверить влияние журналов PostgreSQL и порядка наблюдений
на диагностику отказа аутентификации и обоснованность объяснений.

Инцидент: 20261102T182845Z-bad-password.
Момент диагностики: 2026-11-02T18:33:03Z.

Это продолжение подготовительного исследования.
Сценарий известен исследователю; независимой проверкой
окончательного метода эксперимент не является.

## Варианты контекста

A — описание системы, HTTP-проверки до и во время сбоя,
ошибка подключения из журнала API.

B — сведения из A плюс сообщения PostgreSQL об отказе
аутентификации. Наблюдения сгруппированы по источникам.

C — те же блоки и идентификаторы, что в B, упорядоченные
по указанным временным меткам.

Точность временных меток сохраняется. Порядок событий внутри
одной секунды нельзя устанавливать по меткам с точностью до секунды.
Порядок представления блоков не считается доказательством причинности.

Инструкции и вопросы одинаковы для A, B и C и сохраняются
из первого сравнения. Готовый диагноз в контекст не добавляется.

Действия оператора, конфигурация с намеренно неверным паролем
и сведения после восстановления модели не передаются.

## Условия запусков

Модель, ревизия, параметры генерации и правила сохранения
соответствуют протоколу 003.

Варианты A, B, C; seed 42, 43, 44 — девять основных запусков.
Все ответы сохраняются, независимо от качества.

При случайном повторе пары вариант/seed основным считается
первый завершённый запуск с полным комплектом файлов.
Повтор сохраняется отдельно; причина исключения фиксируется.
Нельзя выбирать основной ответ по его качеству.

## Критерии оценки

Общая шкала: 0 — неверно или отсутствует;
1 — частично правильно; 2 — правильно без существенных противоречий.

1. Проблемный компонент
2 — локализована проблема доступа API к PostgreSQL
на этапе аутентификации, без утверждения об остановке БД;
1 — указана общая проблема доступа к БД;
0 — без оснований выбран другой компонент или остановка БД.

2. Непосредственная ошибка
2 — правильно назван отказ парольной аутентификации stand_admin;
1 — указана только общая ошибка аутентификации или подключения;
0 — названа другая ошибка либо ответа нет.

3. Обоснованность объяснения
2 — сбой запросов связан с отказом аутентификации;
конкретное изменение пароля или конфигурации не объявлено
доказанным. Неверные учётные данные допустимы как гипотеза;
1 — объяснение неполное или чрезмерно уверенное;
0 — объяснение противоречит наблюдениям.
Правило одинаково для A, B и C.

4. Точность использования наблюдений
2 — ссылки, HTTP-коды и временные отношения переданы правильно;
1 — отдельная неточность при верном основном выводе;
0 — существенное искажение доказательств или отсутствие обоснования.

5. Разделение фактов и неизвестного
2 — отказ аутентификации отделён от неизвестных причин:
где возникло несоответствие учётных данных, кто и когда
изменил настройки, если изменения вообще происходили;
1 — неопределённость обозначена неполно;
0 — неизвестные обстоятельства представлены как факты.

6. Дополнительные проверки
2 — предложены две конкретные, применимые и технически
корректные проверки, уточняющие причины отказа аутентификации;
1 — полезна только одна проверка либо рекомендации слишком общие;
0 — полезных проверок нет или действия некорректны.

## Оценка и ограничения

Для каждого балла сохраняются цитата и пояснение.
Оценка с помощью ИИ отмечается как совместная и требует
проверки исследователем; независимой экспертной оценкой не является.

Остальные правила оценки, дополнительные показатели и ограничения
сохраняются из протокола 003. Основной вывод не сводится к сумме баллов.

Вариант A уже содержит явную ошибку аутентификации.
Добавление журнала БД может подтверждать имеющиеся сведения,
не раскрывая новой причины. Улучшение ответов заранее не предполагается.

Результаты двух инцидентов показываются отдельно.
Различия между ними нельзя приписывать только организации контекста:
различаются сами ошибки и диагностическая информативность сообщений.
