## Цель

Проверить сбор наблюдений при недоступности БД
и восстановление сервиса после её запуска.

## Вмешательство

Оператор остановил контейнер db командой Docker Compose stop db.
Контейнер API продолжал работать.
Затем оператор запустил тот же контейнер БД командой start db.

Время начала и завершения команд сохранено в каталоге operator.
Остановка была штатной, а не аварийным завершением процесса.

## Вывод

В этом запуске приложение продолжало отвечать на запросы,
но операции, зависящие от БД, завершались ошибками.
После запуска БД проверенные операции восстановились.

## Ограничения

Проведён один запуск и по одному запросу к каждому адресу
в каждой фазе. Это проверка процедуры, а не статистическая
оценка надёжности или скорости восстановления.

Непрерывного опроса не было, поэтому точные моменты начала
и окончания пользовательского сбоя по этим измерениям
определить нельзя.

Модель на этих данных ещё не проверялась и не обучалась.
Сведения operator и наблюдения after не должны автоматически
попадать в диагностический вход модели. Журналы необходимо
проверить и ограничить временем diagnosis_cutoff.

Исходные файлы results/raw исключены из Git и хранятся локально.
