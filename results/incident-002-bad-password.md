# Инцидент 002: неверный пароль подключения API к PostgreSQL

## Цель

Получить второй контролируемый инцидент с теми же внешними
HTTP-симптомами, что и при остановке БД, но с другой причиной.
Материалы предназначены для исследования влияния диагностического
контекста на способность локальной модели различать причины сбоев.

Это подготовительный эксперимент, а не независимая проверка
эффективности окончательного метода.

## Исходные материалы

Каталог: results/raw/20261102T182845Z-bad-password/
Все времена ниже указаны в UTC.
Момент диагностики: 2026-11-02T18:33:03Z.

Версия кода и состояние рабочего дерева сохранены в operator/.
Конфигурации стенда также сохранены в operator/.

## Действия оператора и известная причина

В DATABASE_URL сервиса API установлен намеренно неверный пароль
через stand/compose.bad-password.yaml.

Пересоздан только контейнер API. Конфигурация PostgreSQL и пароль
пользователя в БД не изменялись. Контейнер БД продолжал работать.

Для восстановления API пересоздан с базовой конфигурацией
stand/compose.yaml.

Эти сведения описывают вмешательство оператора. Они не должны
автоматически включаться в диагностический контекст модели.

## Наблюдения

| Этап | Время | /health/live | /health/ready | /tasks |
|---|---|---:|---:|---:|
| До вмешательства | 18:28:52 | 200 | 200 | 200 |
| Во время сбоя | 18:32:58 | 200 | 503 | 500 |
| После восстановления | 18:34:54 | 200 | 200 | 200 |

Во всех девяти запросах curl_exit_code=0. Это означает успешное
выполнение HTTP-обмена, а не отсутствие ошибок приложения.

Журнал API фиксирует ошибку при вызове connect_db() из list_tasks():

    psycopg.OperationalError: connection failed:
    FATAL: password authentication failed for user "stand_admin"

Журнал PostgreSQL фиксирует два отказа парольной аутентификации
для stand_admin в 18:32:58.878 и 18:32:58.895.

В сопутствующих сообщениях DETAIL указано совпадение подключения
с правилом pg_hba.conf: "host all all all scram-sha-256".
Само наличие этого сообщения не доказывает ошибочность правила.

После восстановления /tasks возвращает ранее созданную задачу
id=2 со статусом in_progress. Сохранность этой записи подтверждена;
полная проверка целостности БД не проводилась.

## Диагностический вывод и ограничения

Непосредственная ошибка — отказ парольной аутентификации.
PostgreSQL отвечает на попытку подключения, но не допускает API
к работе с БД под указанными учётными данными.

Конкретная причина в этом эксперименте — намеренно неверный пароль
в конфигурации API — известна из действий оператора.
Одни сообщения об отказе аутентификации не устанавливают,
кто и где изменил учётные данные.

Во время первого инцидента и этого эксперимента HTTP-коды
одинаковы: 200 / 503 / 500. При этом сообщения об ошибках различны:
ошибка разрешения имени db и отказ парольной аутентификации.

Это обосновывает необходимость сравнить диагностическую ценность
разных наборов наблюдений. Улучшение качества ответов модели
или сокращение времени работы инженера пока не установлены.

## Граница контекста модели

Для диагностики на момент 18:33:03 используются только наблюдения,
полученные не позднее этого времени.

Действия оператора, файл с намеренно неверным паролем и результаты
после восстановления хранятся отдельно от входных данных модели.
