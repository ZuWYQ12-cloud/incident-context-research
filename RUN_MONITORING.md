# Единый запуск наблюдения за сервисом

Команды выполняются из корня репозитория в Ubuntu/WSL. До первого запуска
остановите старые отдельные процессы монитора, интерфейса и отправителя через Ctrl+C.
Защита от второго монитора работает только после обновления monitor_service.py.

Без отправки VK:

```bash
python3 src/run_monitoring.py
```

С реальной отправкой накопленных и новых уведомлений в личный диалог VK:

```bash
python3 src/run_monitoring.py --vk-peer-id 539028488
```

Если VK_COMMUNITY_TOKEN отсутствует в окружении, программа запросит ключ скрыто.
Используйте текущий ключ сообщества, привязанный к этой базе. Ротация остаётся
отдельной явной командой send_vk_notifications.py --rotate-token. Ключ не передаётся
в аргументах, не попадает в журнал запуска и передаётся только процессу отправителя.

Страница: http://localhost:8081. При пустой очереди отправитель ждёт.
Готовность процесса означает завершение его инициализации, а не доступность API,
действительность токена или успешную доставку. Состояние проверяйте в интерфейсе.

База по умолчанию: results/raw/monitor-dev-001.sqlite.
Материалы: results/raw/monitor-incidents.
Журналы каждого запуска: results/raw/monitoring-runs/run-<время UTC>/.
Файлы monitor.log, dashboard.log, vk.log и итоговый status.json сохраняются.
Без VK файл vk.log не создаётся. Пароли и токены не добавляйте в Git.

Docker-стенд запускается отдельно. Единый запуск не запускает и не останавливает
контейнеры: недоступность исследуемого API должна оставаться наблюдаемым событием.
Для выгрузки журналов контейнеров при инциденте:

```bash
sudo -v
python3 src/run_monitoring.py --vk-peer-id 539028488 --compose-file stand/compose.yaml --docker-sudo
```

Разрешение sudo может истечь во время длительной работы; тогда сборщик сохранит
ошибку выгрузки. Для кнопки запуска модели добавьте --model-python "$PWD/.venv/bin/python".
Без этого аргумента сохранённые ответы видны, но запуск новых моделей выключен.

Ctrl+C останавливает дочерние процессы, оставляя Docker-стенд работающим.
После 8 секунд ожидания программа отправляет TERM, затем при необходимости KILL.
Не прерывайте генерацию, если хотите сохранить законченный ответ: прерванное задание
может остаться в промежуточном состоянии и потребовать отдельной проверки.
Остановка во время отправки VK может оставить попытку без подтверждения;
сохранённый random_id используется при повторе, абсолютной гарантии доставки нет.

Если любой компонент неожиданно завершился, даже с кодом 0, остальные останавливаются,
запуск завершается ошибкой и сообщает путь к журналам. Автоперезапуска пока нет.
Таким образом, отказ отправителя также останавливает монитор; после исправления
нужно заново запустить систему. Во время остановки новые проверки не выполняются.
Файлы блокировок не удаляйте вручную: блокировка снимается ОС при закрытии процесса.

Проверка: python3 -m unittest discover -s tests -p 'test_run_monitoring.py' -v
Тесты не отправляют сообщений VK и не меняют состояние Docker-стенда.
